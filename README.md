# WhatsApp Schedule Bot (9-В, №104 ЖББ мектеби)

Бот на WhatsApp Web (`whatsapp-web.js` + Chromium) с веб-страницей для QR-кода.
Отвечает **только на команды** (`/понедельник` … `/пятница`, `/расписание`, `/люди`, `/помощь`) в личных чатах и группах. Обычные сообщения игнорирует.

> ⚠️ `whatsapp-web.js` — неофициальная библиотека. WhatsApp не одобряет такие боты, поэтому используйте второй аккаунт (как вы и планировали) и не рассылайте сообщения без команд.

## Структура
```
src/schedule.js  — расписание (меняется здесь)
src/people.js    — список учеников (меняется здесь)
src/pgStore.js   — хранение сессии в Postgres (Neon)
src/bot.js       — логика WhatsApp, команды, переподключение
src/index.js     — HTTP-сервер + SSE
public/index.html— веб-интерфейс с QR
Dockerfile       — для Render (Chromium внутри)
```

## 1. Установка
```bash
npm install
cp .env.example .env
```
Нужен Node.js 18+.

## 2. Запуск локально
```bash
npm start
```

## 3. Веб-интерфейс
Откройте http://localhost:3000

## 4. Как отсканировать QR
На телефоне: WhatsApp → **Настройки → Связанные устройства → Привязка устройства** → наведите камеру на QR на странице. После подключения QR исчезнет и появится «✅ WhatsApp подключён».

## 5. Проверка команды
С другого номера (или в группе, где есть бот) напишите `/понедельник` — бот пришлёт расписание.

## 7. Развёртывание на Render
1. render.com → **New → Web Service** → выберите репозиторий.
2. **Runtime: Docker** (используется `Dockerfile`, в нём уже есть Chromium).
3. Для сохранения сессии: добавьте `DATABASE_URL` от Neon (диск не нужен).
4. Нажмите Deploy, откройте `https://название-сервиса.onrender.com` и отсканируйте QR.

## 8. Переменные окружения Render
| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | строка подключения Neon (рекомендуется) |
| `SESSION_PATH` | `/data/sessions` (только если используете Disk вместо Neon) |
| `PUPPETEER_EXECUTABLE_PATH` | `/usr/bin/chromium` (уже задано в Dockerfile) |

`PORT` Render задаёт сам.

## 9. Как работает сохранение сессии
Используется `LocalAuth`: данные входа (профиль Chromium) лежат в `SESSION_PATH`. При перезапуске бот берёт их оттуда и QR не нужен. Если вы вышли из аккаунта или сессия повреждена, бот перезапускается и снова показывает QR.

## Хранение сессии в Neon Postgres (бесплатно, без диска Render)
1. neon.tech → создайте проект → скопируйте **Connection string** (с `sslmode=require`).
2. Добавьте переменную `DATABASE_URL` (локально в `.env`, на Render в Environment).
3. Запустите бота и отсканируйте QR. В логах появится «Сессия сохранена в базе данных» (примерно через минуту после входа).
4. После перезапуска или деплоя бот сам берёт сессию из базы, QR не нужен.

Если `DATABASE_URL` пуст, используется локальная папка `SESSION_PATH`. Disk на Render при этом не нужен.
Подождите хотя бы 1–2 минуты после первого сканирования, прежде чем перезапускать сервис, иначе первое сохранение не успеет произойти.

## 10. Ограничения на Render
- **Файловая система ephemeral**: без Disk сессия стирается при каждом деплое/перезапуске — QR придётся сканировать заново. Решение: платный Disk (`/data`) либо `RemoteAuth` с MongoDB (`wwebjs-mongo`) — сессия хранится в базе.
- **Бесплатный план засыпает** после ~15 минут без HTTP-запросов — бот в это время не работает. Для 24/7 нужен платный план (или внешний пинг `/health`, но это не гарантия и нарушает смысл free-плана).
- Chromium требует памяти (≈400–500 МБ); на 512 МБ возможны падения. Бот перезапускает браузер с нарастающей паузой (5→60 с) и не плодит процессы.
- Кнопки WhatsApp в неофициальных клиентах нестабильны, поэтому меню `/расписание` текстовое.

## Вариант без сайта: QR в Termux → сессия в Neon → Render
1. В Termux: `pkg update && pkg install tur-repo && pkg install nodejs git chromium`
2. `export PUPPETEER_SKIP_DOWNLOAD=true && npm install`
3. `export DATABASE_URL="строка_Neon"` и `npm start`
4. В консоли появится QR (уменьшите масштаб экрана щипком). Отсканируйте его **с другого телефона/устройства**.
5. Дождитесь в консоли «Сессия сохранена в базе данных», затем остановите бота (Ctrl+C).
6. На Render укажите ту же `DATABASE_URL` — бот подхватит сессию без QR.
Не запускайте бота одновременно в двух местах.

## Привязка по коду (если QR не сканируется)
Задайте `PAIR_PHONE=номер_аккаунта_бота` (цифры, с кодом страны). В консоли и на сайте появится 8-значный код.
WhatsApp → Связанные устройства → Привязка устройства → **Привязать по номеру телефона** → введите код. Работает и на том же телефоне.
